# MST Kruskal and Prim Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add minimum spanning forest implementations using Kruskal and Prim, verify both with tests, and document the API.

**Architecture:** Add an MST result type and static algorithm methods in `algorithms.MST`. Kruskal sorts each undirected edge once and uses the existing DSU; Prim grows each component using a priority queue and restarts at the next unvisited vertex. Both return selected edges, total weight, and component count.

**Tech Stack:** Java 17, Maven, JUnit 5, existing `graph.Graph`, `graph.Edge`, and `algorithms.DSU`.

**Spec:** Assignment 3 PDF, section 3 “MST: Kruskal & Prim”.

## Global Constraints

- Kruskal sorts edges by weight and includes an edge only when its endpoints have different DSU representatives.
- Prim starts at vertex 0 when present and uses `PriorityQueue`; already visited vertices are skipped.
- Disconnected graphs produce a minimum spanning forest and component count, without throwing.
- On the same graph, both algorithms produce equal total weights; trees may differ.
- Preserve existing graph/DSU APIs and Java 17 compatibility.
- Keep pre-existing staged IDE files and untracked user files out of feature commits.

## Review Focus

- Empty graph and isolated vertices: zero weight and all components reported.
- Negative, equal, and extreme integer edge weights: correct ordering and long total weight.
- Self-loops, parallel edges, and cycles: no redundant selected edges.
- Disconnected graph: both methods return a forest with `V - components` edges.
- Directed input: reject clearly because MST is defined for undirected graphs.
